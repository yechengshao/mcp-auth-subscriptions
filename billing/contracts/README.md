# Local contract foundation

Run `npm ci` then `npm run check` from the repository root with Node 24+. TypeScript compiles before Node's built-in tests run. Tests share one process (`--test-isolation=none`) so this environment reports individual cases rather than only file summaries. No cloud credentials or services are required. Fixtures under `tests/fixtures/` are synthetic and must never be published as an offer catalog.

| Implemented artifact | Scope |
|---|---|
| `schemas.ts` | Strict schemas for catalog, purchased snapshot, entitlement, order, native requests, failure results and billing queue references |
| `validate.ts` | Environment/account checks, unique tier ordering, enabled duration/action selection, immutable snapshot copies, public display filtering, identity tuple hashing and owner-scoped record/reference checks |
| `storage.ts` | Twelve billing record kinds, exact keys, upgrade math/digest, reservation evidence and reconciliation generation/dispatch invariants |
| `results.ts` | Typed success/pending/failure payloads and browser status mapping, with support-only financial paths |
| `configuration.ts` | Required bounded budgets, visibility/concurrency constraints and exact projection-read/billing-alias grant fragments |
| `catalog-cache.ts` | Versioned cloned values, concurrent-load coalescing, maximum 60-second cache/three-second fetch, abort and fail-closed refresh |
| `service-term.ts` | Exclusive expiry from a verified-payment timestamp, fixed UTC days and original-day calendar clamping |
| `../../access/contracts/` | Eight access record kinds, purpose-bound transaction/session identity, cleanup, credential lifetimes, mutation-generation shape and provisioning budgets |

Schemas reject unknown fields and unsupported versions without coercion or silently removing fields. Validation failures return fixed internal codes without reflecting submitted values. The service-term JSON Schema in specs remains authoritative and is imported into the emitted build; other executable schema objects are exported from the TypeScript modules.

The catalog uses keyed `plans`/`duration_options` objects. Each plan has `display`, `actions`, `usage_mapping` and purchase state; each duration has `label`, `service_term`, `amount_minor`, `currency`, `product_id`, `price_id`, `mode=payment` and purchase state. Plan/duration identifiers use ASCII letters, digits, underscores and hyphens, at most 128 characters. Currency uses lowercase three-letter codes; enabled prices must be positive integer minor units. `ssm_version` is the purchased positive parameter version. These validators cannot prove that a referenced AWS resource or Stripe price exists or matches the configured amount.

Record discriminators and keys are exported in `billingRecordSchemas` and `accessRecordSchemas`; fixtures cover every registered kind and reject extra fields, wrong versions/keys/environments and unsafe cleanup. Financial, identity and subscriber-binding records omit TTL. Temporary login/credential records retain separate logical deadlines and cleanup horizons; consumed credentials remain readable tombstones, not usable authority. State/field validation cannot enforce conditional writes, one-use redemption or exactly-once provider effects.

The physical choices include 16-digit HISTORY revision padding, 12-digit due-work timestamp padding, explicit processing/dispatch lease objects and a separate purchased snapshot in each subscription/quote/history item. Quote digests hash canonical sorted JSON over the immutable field list in `quoteDigest`; they detect snapshot inconsistency, not authenticate browser-supplied quotes. Orders with `intent=upgrade` require quote/credit/net-price fields; the catalog snapshot retains the full price. All provider evidence must still be verified by the future billing adapter before it is stored.
Native requests are trusted IAM envelopes, not browser payloads. Shape validation is not caller authentication. Failure codes are closed per outcome; unknown combinations reject. Success/pending payloads and JSON status mapping are validated; actual HTTP dispatch, support rendering and caller/ownership authorization remain unimplemented. Validating a `manageSubscription` or `openPortal` request does not authorize an action or implement a provider mutation.

Session-context validation accepts server-loaded records only. It does not implement cookie issuance, Cognito verification, CSRF comparison, callback routing, session rotation or database transactions. The catalog loader is injected and tested locally; its future SSM adapter must enforce exact IAM and the shared logging/tracing contract. Pure validators emit no logs/spans or raw input errors; caller-owned telemetry and sentinel-redaction tests remain mandatory when handlers/adapters are added.

B001's contract/schema/fixture prerequisite is complete. T014/T022, B002/B003 and later runtime tasks remain open. These tests do not prove AWS native-key uniqueness, lease takeover, credit reservation atomicity, provider evidence, real IAM, CloudWatch/X-Ray delivery or client behavior. B001 baseline evidence is 60 tests with passing typecheck/build; the current suite also includes [monitoring tests](../../observability/README.md); all live checks are not_run. Operator budgets/IDs/prices are still required before deployment; synthetic fixture values are not production defaults.
